**October 22–November 25, 2026 | Red**

## Findings

- Archive: 13,669 entries, 13,668 payload files; every payload hash and size verified. CRC checks all passed. `.manifest-pre` appears only in manifest (temporary build entry); final manifest appears only in ZIP. No evidence hash failure.
- Primary AD-4.27 logs: 3,315 D: records + 1,504 C: records + 4,014 Linux records + one duplicate rescue copy = 8,834 source occurrences / 8,833 unique measured engine records. 230 actual launch banners including no-request starts. All 8,834 request summary lines parsed; 59 partial-prefill records preserved.
- Exact whole-primary measured workload: 52,806,821 fresh, 685,636,054 reused, 5,574,618 generated; 103,263,862 ms prefill and 295,995,579 ms decode. Weighted rates 511.38 and 18.83 t/s. This is a mixed-era descriptive total, not a standard benchmark.
- Separate 1,517 experimental/alternate-model engine records (809 AD427 experimental, 685 Swift, 23 Orca); these are source occurrences, not an extra production total. Independent bench result JSONs and configs separately cataloged. 110 exact config files cataloged.
- After excluding 99 identified/known trial rows and the 111 likely controlled batch, the production-candidate set is 8,623 requests, 51,193,233 fresh @508.68, 682,453,566 reused, 5,518,335 output @18.83. Candidate set includes 72 purpose-unresolved promotion/retest or experimental-binary records; do not label it certified production-only. 493 primary rows independently confirmed by archived dashboard/ReBAR data. Remaining raw log requests lack reliable workload-type labels.

## How to use the appendices

- `request_ledger_final.csv`: 8,833 deduplicated primary rows, per-row source path and line, raw engine fields, actual vs requested fresh, exact timing, status, cache hits, launch, tune family, classification, available wrapper/dashboard/clock provenance. No invented per-request timestamps for older Windows rows.
- `per_tune/`: same unique ledger split by tune family, plus totals in chronological table. `fine_state_totals.csv`: precise launch-state splits; do not sum both table and fine totals together.
- `requests_all_sources.csv`: duplicate rescue record retained with duplicate link. `engine_launches.csv`: complete commands, admitted RAM, I/O startup evidence and version; zero-request windows included.
- `journal_reconciliation.csv`: 3,356 wrapper completions including 12 no-speed records; 3,346 engine links, 10 unmatched. Links based on exact signatures or bounded near-match, match type retained. `wrapper_requests.csv` is intermediate numeric-rate extraction; journal reconciliation supersedes it for journal status/counts.
- `dashboard_reconciliation.csv`: 413/413 archived rows matched, including 15 stop/closed rows with up to 2 fewer displayed output tokens and one partial-prefill row identified by actual processed prompt. `rebar_reconciliation.csv`: 80/80 links. `clock_turns.csv`: 74/74 independent telemetry links.
- `experimental_engine_records.csv`: experimental/alternate-model raw request rows, not part of primary totals. `benchmark_summary.csv`: 4x4 local result JSONs; post2 benchmark sample mean is not a weighted production decode metric.
- `config_catalog.csv`: exact archived JSON arguments/env and manifest provenance. Source archive and historical notes remain original evidence; analysis scripts reproduce the extraction.
